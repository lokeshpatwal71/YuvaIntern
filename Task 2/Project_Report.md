## 3. Introduction

Data analysis is the process of examining data to find useful information such as totals, averages, comparisons and trends, so that better decisions can be made. Organisations such as supermarkets create thousands of records every day, and tools such as Python make it possible to clean, summarise and visualise this data quickly.

This project, **Hands-On Data Lab Implementation**, builds a working data analysis environment using Python, Jupyter Notebook, pandas, NumPy, Matplotlib and Seaborn, and uses it to complete practical exercises on a supermarket sales dataset: data cleaning, data manipulation, exploratory data analysis (EDA), visualization and basic statistical analysis.

## 4. Problem Statement

A supermarket chain with three branches records every customer invoice, but the raw records contain data-entry problems and nobody has examined them. The problem addressed in this project is: **how can we set up a Python data lab, clean the sales records and use data manipulation, visualization and basic statistics to understand sales performance** (which products, branches, customers and times of day generate the most revenue, and whether customer ratings depend on spending)?

## 5. Objectives

## 11. Data Cleaning

| Problem found | Action taken | Result |
|---|---|---|
| 6 duplicate invoices (same Invoice ID entered twice) | `drop_duplicates()` | 1006 rows reduced to 1000 rows |
| 12 missing ratings | Filled with the median rating (7.0) | 0 missing values |
| Payment typed in 8 different ways | `str.strip().str.capitalize()` | 3 payment methods |
| `Date` and `Time` stored as text | `pd.to_datetime()` with explicit format; `hour` column extracted | Proper date type; date range 01 January 2025 to 31 March 2025 |
| Column names with spaces and symbols | Renamed with a dictionary | e.g. `Tax 5%` became `tax_5pct` |
| `gross margin percentage` constant, `gross income` equal to `Tax 5%` | Columns dropped | 17 columns reduced to 15 |
| 24 high-value invoices (IQR rule) | Checked and **kept**: they are genuine large purchases | Reported in the statistics |

After cleaning, validation checks confirmed unique invoice IDs, no missing values, quantities between 1 and 10, positive prices and ratings between 1 and 10.

## 17. Challenges

(Edit this section so that it describes the difficulties you really faced.)

* **Understanding the data types:** `Date` was stored as text and had to be converted using the correct format (month/day/year) before months and hours could be extracted.
* **Finding hidden problems:** the payment column looked fine at first; `value_counts()` revealed 8 spellings of 3 methods, and duplicates had to be checked with both `duplicated()` and the Invoice ID.
* **Deciding what to do with outliers and missing values:** large invoices were genuine, so they were kept; blank ratings were filled with the median.
* **Interpreting results correctly:** the mean was misleading for skewed data, February seemed to have lower sales only because it is shorter, and high correlation between total and price is a result of the formula, not a discovery.
* **File paths:** the notebook and script are in different folders, so relative paths (`../data/dataset.csv`) and path handling with `pathlib` were needed.
